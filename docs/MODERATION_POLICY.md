# Модерация контента

Как устроена модерация «Гармонии», какие решения принимаются автоматически
и что может сделать человек. Интеграция внешнего классификатора —
[MODERATION.md](MODERATION.md).

---

## Принципы

**1. Обратимое предпочтительнее необратимого.**
Автоматическое скрытие отправляет контент на ручную проверку: автор ждёт и
может обжаловать. Автоматическое удаление — нет. Поэтому автоматика только
скрывает, а решение принимает человек.

**2. Решение объяснимо.**
Каждая мера попадает в журнал с причиной, модератором и временем. Ответ на
жалобу можно объяснить, решение — обжаловать.

**3. Обжалование реально.**
Письмо о решении содержит адрес старшего модератора. Решение, на которое
нет апелляции, — это не модерация, а цензура.

**4. Прозрачность для автора, анонимность для жалобщика.**
Автор знает, что его публикацию скрыли или удалили, и почему. Жалобщик не
знает, что произошло: иначе массовые жалобы становятся оружием.

## Двухслойная модерация

```
       Текст
         │
         ▼
┌─────────────────────────┐
│  Локальный анализатор   │  PII · угрозы · язык ненависти
│  (всегда включён)       │  опасный контент · спам · инъекции
└────────────┬────────────┘
             │  allow · review · block
             ▼
┌─────────────────────────┐
│  Внешний классификатор │  может только УСИЛИТЬ решение
│  (необязателен)         │  никогда — ослабить
└────────────┬────────────┘
             │
             ▼
        allow · review · block
```

Асимметрия принципиальна. Если бы внешний слой мог ослабить вердикт, его
сбой, исчерпание квоты или ошибка в конфигурации стали бы обходом модерации.

### Что ловит локальный слой

| Категория | Примеры | Решение |
|---|---|---|
| Угрозы | «найду тебя и убью» | block |
| Язык ненависти | по расе, национальности, ориентации | block |
| Несовершеннолетние в секс-контенте | — | block |
| Банковские карты, документы | `4276 3800 …` | block |
| Ключи, кошельки, СНИЛС | — | block |
| Паспортные данные | — | block |
| Ссылки на запрещённое | — | review |
| Контактные данные | «пиши в тг @…» | review |
| Ссылочные фермы | 5+ ссылок | review |
| Инъекции | `<script>`, `onerror=` | блокируется санитайзером |
| Спам-маркеры | «вступайте в группу», крипто-реклама | review |

Контактные данные — не block: оставить свой контакт в посте на социальной
сети нормально, поэтому такие случаи уходят на проверку.

### Пороги

| Порог | Значение | Смысл |
|---|---|---|
| `MODERATION_REVIEW_THRESHOLD` | 0.55 | Ниже — на проверку |
| `MODERATION_BLOCK_THRESHOLD` | 0.85 | Выше — отклонить |

Категории `threat`, `hate`, `sexual` блокируются независимо от оценки: для
них не существует «почти опасного» контента.

## Жалобы

### Подача

Пользователь выбирает причину из одиннадцати и может приложить контекст.
Отправка занимает два нажатия: высокий порог входа делает жалобы
формальными.

### Дедупликация

Один пользователь — одна жалоба на объект. Без этого один аккаунт мог бы
заполнить очередь, отодвинув настоящие жалобы.

### Автоматическая эскалация

Контент скрывается, когда его отметили **разные** люди: минимум
`MIN_DISTINCT_REPORTERS_FOR_AUTO_HIDE` (2) различных жалобщика.

Считаются именно люди, а не жалобы. Один пользователь может подать только одну
жалобу на объект (см. выше), поэтому «разные люди» и «две жалобы» совпадают —
но правило сформулировано через людей намеренно: именно так выглядит настоящая
сигнализация, и именно её может подделать один аккаунт.

Порог настраивается через `AUTO_HIDE_REPORT_THRESHOLD`, но оператор может его
поднять и не может опустить ниже `MIN_DISTINCT_REPORTERS_FOR_AUTO_HIDE`: менее
двух независимых жалобщиков автоскрытие не включается никогда.

### Что видит жалобщик

Только «жалоба принята». Ни решения, ни числа других жалоб, ни факта
скрытия. Сообщение «3 человека уже пожаловались» превращало бы жалобу в
инструмент давления.

### Что видит автор

Уведомление с причиной и адресом для апелляции. Молчаливое удаление чужого
контента недопустимо.

## Санкции

| Мера | Срок | Последствие |
|---|---|---|
| Скрыть | до решения | Не в ленте, в профиле |
| Предупреждение | — | Счётчик +3 при достижении лимита — приостановка |
| Приостановить | 1 ч … 12 мес. | Сессии отзываются немедленно |
| Заблокировать | навсегда | Вход невозможен |
| Восстановить | — | Отмена санкции |

Счётчик предупреждений: три предупреждения приводят к автоматической
приостановке. Это даёт обратную связь до серьёзной меры, а не после.

Истечение срока обрабатывает `moderation.expire_actions` раз в час: временная
приостановка снимается сама, без напоминания.

### Ограничения для себя

- нельзя применить меру к собственному аккаунту;
- модератор не может менять роли — только администратор;
- модератор не может блокировать администратора.

## Панель модератора

`/admin` — очередь, пользователи, журнал действий.

Очередь отсортирована по приоритету причины, затем по времени. Высокий
приоритет у насилия и угроз (`critical`), низкий у спама.

Каждая карточка жалобы содержит **всё нужное для решения без второго
запроса**: текст, автора, его историю (предупреждения, прошлые жалобы,
предыдущие меры) и самое важное — сколько всего жалоб на этот объект.

Это не удобство, а требование: решение, принятое вслепую, почти наверняка
ошибочно.

### Допуск

- `/admin/*` — модератор и администратор
- смена ролей и статусов — только администратор
- роль проверяется декоратором **до** тела обработчика: новый маршрут в
  `/admin` защищён по умолчанию

## Журнал

Каждая мера — строка в `moderation_actions`: действие, субъект, объект,
модератор, причина, срок, отзыв. Записи не удаляются, а только отзываются
новой записью: история должна быть полной.

Параллельно ведётся `audit_logs` — шире, чем модерация: входы, смены ролей,
удаления аккаунтов, экспорты данных.

Журналы **не содержат содержимого сообщений**. Только идентификаторы,
действия и причины. IP-адрес — в виде необратимого HMAC-хеша: это
персональные данные, и хранить их в открытом виде незачем.

## Ограничения

| Ограничение | Следствие |
|---|---|
| Списки слов обходятся леетспиком | Локальный слой ловит очевидное; нюансы — внешний классификатор |
| Угрозы, выраженные иначе, не распознаются | Апелляция и ретроспектива |
| Автомодерация без языковой модели не понимает контекст | Порог на проверку, а не на удаление |
| Полная модерация изображений требует отдельного сервиса | Сейчас — только структурная проверка |
| Нет автоматического снятия санкции за хорошее поведение | Только по сроку или вручную |
