# Тестирование

Набор проверяет **свойства** системы, а не строки реализации. Каждый тест
должен падать, если свойство перестанет выполняться, — и не падать от
косметических изменений.

---
## Запуск


```bash
make test            # весь набор
make test-fast       # до первого падения
make test-cov        # с покрытием
```

```bash
cd backend
pytest tests/test_security.py -v                    # один файл
pytest -k "csrf or enumeration" -v                  # по смыслу
pytest -x --lf                                       # последние упавшие
HARMONY_DEBUG_ERRORS=1 pytest tests/test_posts.py   # трассировка 500
```

---

## Отладка

`HARMONY_DEBUG_ERRORS=1` заменяет обработчик ошибок на тот, что печатает
трассировку. Без переменной приложение ведёт себя ровно как в production.
Обработчик ставится один раз на приложение — Flask запрещает регистрировать
обработчики после первого запроса, поэтому фикстура вешает его в `app`, а не
в отдельную фикстуру на каждый тест.

```bash
HARMONY_DEBUG_ERRORS=1 pytest tests/test_social.py::TestChat -x
```

`flask routes` показывает реальные адреса — полезно, когда тест ищет
маршрут, которого нет.

## Проверки вне pytest

Часть контракта проверяется скриптами, потому что это не свойство бизнес-логики,
а свойство согласованности артефактов.

| Команда | Что ломает |
|---|---|
| `python tools/build_openapi.py --check` | `openapi.json` разошёлся с `openapi.yaml` |
| `python tools/check_routes.py` | Есть маршрут без документации или документированная операция без маршрута |
| `python tools/check_frontend.py` | Модуль импортирует несуществующий файл; появился `innerHTML` вне пересмотренных мест |
| `make lint` | Форматирование и типичные ошибки |
| `bandit -r backend/app -ll` | Опасные конструкции |

Все четыре входят в `make check`, поэтому локальная проверка перед коммитом
покрывает ровно то же, что и CI.

---

## Чего в наборе нет

- **Тестов интерфейса.** Фронтенд — ES-модули без сборки; `check_frontend.py`
  проверяет граф импортов и точки `innerHTML`, но не поведение DOM.
- **Нагрузочного тестирования.** Описан в `docs/RUNBOOK.md` как ручной сценарий
  с `k6`; автотест на нескольких машинах в этом репозитории был бы дороже
  пользы.
- **Проверки вёрстки.** Дизайн-система меняется чаще, чем тестируется
  скриншотами, и такие снимки устаревают быстрее, чем приносят пользу.
