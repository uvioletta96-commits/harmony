# Модель угроз и модель безопасности

Документ отвечает на два вопроса: от чего защищается платформа и почему
каждая мера выбрана именно так. Он предназначен для ревью безопасности и для
того, чтобы следующий разработчик не сломал свойства случайно.

## Активы

| Актив | Ценность | Что защищает |
|---|---|---|
| Пароли | Полный захват аккаунтов | bcrypt, соль, отсутствие восстановления |
| Сессии | Действия от имени пользователя | HttpOnly-cookie, ротация, отзыв |
| Личные сообщения | Самое чувствительное, что есть | TLS, доступ по членству, срок хранения |
| Персональные данные | Правовая ответственность | Минимизация, сроки, выгрузка, удаление |
| Целостность контента | Доверие к площадке | Модерация, журнал действий |
| Доступность | Репутация сервиса | Ограничения, ретраи, деградация |

## Нарушители

| Кто | Возможности | Основная цель |
|---|---|---|
| Бот-регистратор | Много аккаунтов, автоматизация | Массовые публикации, реклама |
| Скрапер | Только чтение | Сбор пользователей и контента |
| Захватчик аккаунта | Украденные пароли | Читание переписки, рассылка фишинга |
| Инсайдер площадки | Доступ к данным изнутри | Профиль пользователей |
| Злонамеренный пользователь | Локальная репутация | Травля, домогательства, разжигание |
| Ошибка конфигурации | Случайный доступ | Утечка, недоступность |

## Поверхность атаки

```
Публично
  GET/POST /api/v1/*        REST
  /socket.io/               WebSocket
  /uploads/*                изображения
  /healthz /readyz /metrics диагностика

Внутренне
  PostgreSQL                данные
  Redis                     кэш, лимиты, очереди
  SMTP                      транзакционные письма
  Объём /backups            дампы с персональными данными
```

`/metrics` закрыт nginx для внешних адресов: метрики раскрывают форму
трафика, коды ошибок и внутренние пути.

## Меры защиты

### Аутентификация

| Угроза | Мера |
|---|---|
| Подбор пароля | bcrypt (12 раундов), ограничение частоты, блокировка при серии неудач |
| Кража токена через XSS | `HttpOnly` + `Secure` + `SameSite` |
| Кража файлов cookie | Политика CSP без `unsafe-inline` для скриптов |
| Повтор refresh-токена | Ротация; повтор отзывает **все** сессии |
| Использование старого токена после санкции | `ver` в claims + проверка статуса на сервере |
| Удаление аккаунта украденной сессией | Step-up: пароль обязателен |
| Перебор с разных IP | Ограничение по идентификатору и по адресу |

### Пароли

- Хеш bcrypt, соль уникальна на пользователя
- Минимум 10 символов, минимум два типа символов
- Блок-лист распространённых паролей
- Запрет на четыре одинаковых символа подряд
- **Строгие правила состава намеренно не применяются.** Требование
  «одна заглавная, одна цифра, один символ» измеряемо *снижает* энтропию:
  люди отвечают предсказуемыми заменами. Требование длины и разнообразия
  работает лучше

> Байты после 72-го bcrypt игнорирует. Пароли длиннее предварительно
> хешируются SHA-256, иначе суффикс перестал бы влиять на результат.

### Перечисление аккаунтов

| Эндпоинт | Поведение |
|---|---|
| `/auth/login` | Одинаковое сообщение и одинаковая работа для любого логина |
| `/auth/register` | Поле указывает, что занято (необходимо для формы) |
| `/auth/forgot-password` | Всегда одинаковый ответ |
| `/auth/resend-verification` | Всегда одинаковый ответ |
| `/users/<id>` | 404, а не 403 — иначе неявная приватность утекает |

На неизвестный логин выполняется bcrypt-проверка фиктивного хеша, чтобы время
ответа не отличалось.

### CSRF

Двойная отправка: значение из `harmony_csrf` отражается в `X-CSRF-Token`.
Принимается также корректный `Origin`/`Referer` — иначе не работали бы
мобильные клиенты и `curl`. Проверка выполняется **до** обработчика, а не в
нём, поэтому новый эндпоинт защищён по умолчанию.

### XSS

Три независимых слоя:

1. **Архитектурный.** Пользовательский контент — обычный текст. API не
   возвращает HTML; фронтенд использует `textContent`. Путь инъекции закрыт
   по построению, а не фильтрацией.
2. **Политика.** CSP без `unsafe-inline` для скриптов. Даже если
   инъекция каким-то образом проникнет, она не выполнится.
3. **Очистка на входе.** Второй слой: снимаются теги, двойное кодирование,
   управляющие символы, невидимые и двунаправленные символы.

Схемы `javascript:`, `data:text/html`, `vbscript:` отклоняются. Пробелы и
управляющие символы внутри схемы (`java\tscript:`) нормализуются перед
проверкой.

### Ограничение частоты

Скользящее окно в Redis, атомарно через Lua. Фиксированное окно позволяло бы
выдать 2× лимита на стыке двух окон; отсортированное множество этой дыры не
имеет. При недоступности Redis — локальный счётчик: защита действует в рамках
процесса.

### Ограничения

| Действие | Лимит |
|---|---|
| Вход | 10/мин · 5/час |
| Регистрация | 5/час · 20/сутки |
| Публикация | 20/час |
| Комментарий | 60/час |
| Сообщение | 120/мин |
| Загрузка | 30/час |
| Поиск | 120/час |
| Жалоба | 20/час |
| Глобально | 1200/час |

### Спам и боты

Оценивающая система: слабый сигнал сам по себе не блокирует, совокупность —
блокирует. Сигналы затухают за 24 часа, поэтому разовая оплошность не
наказывается спустя сутки.

| Сигнал | Вес |
|---|---|
| Заполненная ловушка (honeypot) | 5.0 |
| XSS-полезная нагрузка | 4.0 |
| Решено подозрительно быстро | 2.0 |
| Дубликат контента | 2.0 |
| Много ссылок | 1.5 |
| Всплеск публикаций | 1.5 |
| Массовые жалобы | 1.5 |

Порог блокировки — 6.0.

стороннего сервиса и не передаёт данные третьим лицам. Это контроль стоимости,
а не доказательство человечности; при строгих требованиях доступности
используйте Turnstile.

### Загрузка файлов

| Угроза | Мера |
|---|---|
| Исполняемый файл с картинкой | Определение по сигнатуре, а не по расширению |
| Переполнение буфера | Pillow `verify()` до декодирования, лимит на `MAX_IMAGE_PIXELS` |
| Бомба декомпрессии | Ограничение числа пикселей, отклонение 80 Мпикс |
| Утечка геолокации | Перекодирование: EXIF не переживает повторное сохранение |
| Захват чужого изображения | `owner_id` в строке загрузки; привязка только владельцем |
| Заполнение диска | `maintenance.purge_orphan_uploads` удаляет невостребованные файлы |
| XSS через SVG | SVG не принимается |

Клиент не может указать URL, размеры или MIME-тип: он присылает
`storage_key`, а сервер читает фактические метаданные из своей записи.

### Авторизация

| Мера | Описание |
|---|---|
| `public_id` вместо `id` | Невозможно перебирать, не раскрывается объём |
| Непрозрачные `public_id` в URL | 128 бит случайности |
| Проверка членства в чате | Не-участник получает 404, а не 403 |
| Роли на декораторе | Новый маршрут `/admin/*` защищён по умолчанию |
| Статус аккаунта на сервере | Заблокированный пользователь с живым токеном отклоняется |

### Утечки через ошибки

Клиент получает `code`, `message`, `request_id`. Трассировка и детали
внутреннего исключения остаются в логах и попадают в ответ только в режиме
отладки. `request_id` связывает сообщение пользователя с записью в журнале.

### Аудит

Неизменяемый журнал действий модераторов и значимых событий. Хранит
идентификаторы, действия и причины — **не** содержимое сообщений. IP-адрес
хранится как HMAC-хеш с солью установки: это персональные данные, и в открытом
виде они не хранятся.

### Транспорт

HSTS, принудительный HTTPS, `Secure` и `HttpOnly` у cookie, заголовки
безопасности на каждом ответе, HSTS-preload выключен по умолчанию (его
включают только после подтверждения, что домен обслуживается исключительно по
HTTPS: ошибка здесь блокирует домен на год).

## Решения с обоснованием

### Почему `HttpOnly`-cookie, а не `localStorage`

`localStorage` читается любым скриптом на странице. Достаточно одной
инъекции, чтобы 12-часовой токен был украден. `HttpOnly`-cookie недоступна из
JavaScript. Цена — CSRF-защита, которая здесь и реализована.

### Почему content в виде обычного текста

Санитайзер — это фильтр, а фильтры обходятся. Единственный надёжный способ
не выполнить пользовательский ввод — никогда не отдавать его парсеру HTML.
Текст с типизированными сегментами (`link`, `mention`, `hashtag`) даёт
ссылки и подсветку без единого куска пользовательской разметки.

### Почему асимметричная модерация

Внешний классификатор может только **усилить** решение локального слоя. Иначе
его сбой, исчерпание квоты или неверная настройка превращаются в обход
модерации. `MODERATION_FAIL_CLOSED=true` дополнительно отправляет всё на
ручную проверку при недоступности классификатора.

### Почему контент скрывается по автоматической эскалации

Ложное срабатывание стоит автору нескольких минут ожидания и обжалования.
Ложное отсутствие реакции на действительно опасный контент необратимо.
Асимметрия выбрана в пользу обратимости.

### Почему удаление аккаунта отложено

Немедленное необратимое удаление из-за одной ошибки необратимо. Льготный
период даёт пользователю возможность передумать и системе — окно на отмену
ошибочной массовой операции.

### Почему аудит переживает удаление

Журнал действий модераторов — юридическая запись, а не профиль. Удаление
связи с аккаунтом сохраняет возможность объяснить и обжаловать решение, не
сохраняя о пользователе ничего, что его идентифицирует.

## Известные ограничения

Честный перечень того, чего система не делает.

| Ограничение | Следствие | Что сделать |
|---|---|---|
| Нет 2FA (TOTP) | Пароль — единственный фактор | Подключить внешний IdP по OIDC |
| Нет сквозного шифрования переписки | Сервер видит сообщения | E2EE с серверными публичными ключами |
| Спам-фильтр опирается на списки слов | Легко обходится леетспиком | Внешний классификатор уже поддержан |
| Аватар — ссылка, не файл | Внешний URL может утечь IP | Своё хранилище с проксированием |
| Нет федерации (ActivityPub) | Закрытый периметр |Federation как отдельный проект |
| Поиск по хэштегам без трендового окна | Популярное не выделяется | Ограниченный кеш на сутки |
| `matchead` | — | — |

## Что мониторить

| Событие | Правило |
|---|---|
| Входы `auth.login_failed` | Рост относительно базовой линии — Credential stuffing |
| Срабатывания `ratelimit.exceeded` | Всплеск — атака или сломанный клиент |
| `moderation.blocked` | Всплеск — возможна ложная настройка |
| `spam.signal` с весом > 3 | Целенаправленная автоматизация |
| `admin.role_change` | Любая смена роли |
| `account.purged` | Неожиданная волна — вероятна ошибка скрипта |
| `db.slow_query` | Нет индекса |
| `celery.task_failed` | Сломанная задача |
| `maintenance.backup_stale` | Бэкапа нет более 48 часов |

Все события пишутся как `action: "domain.event"` — стабильное имя для
алертинга и дашбордов.

## Реагирование на инцидент

### Утечка учётных данных

```bash
# 1. Отозвать все сессии
docker compose exec backend flask shell
>>> from app.models.user import UserSession; from app.models.base import utcnow
>>> from app.extensions import db
>>> db.session.query(UserSession).filter(UserSession.revoked_at.is_(None)).update(
...     {"revoked_at": utcnow(), "revoked_reason": "incident"})
>>> db.session.commit()

# 2. Сменить JWT_SECRET_KEY (инвалидирует все токены) и перезапустить
# 3. Сменить пароль затронутым пользователям через принудительный сброс
```

### Скомпрометированный `SECRET_KEY`

Смена немедленно разлогинивает всех и обесценивает CSRF-токены. Планируйте
на тихое время; предупредите пользователей заранее.

### Утечка через резервные копии

Остановите сервис `backup`, сохраните копии для расследования, удалите
компрометированные, ротируйте доступ, оцените обязанность уведомления
(ст. 33 GDPR: уведомление в течение 72 часов).

### Злонамеренный модератор

Журнал аудита содержит все действия с идентификаторами. Отзовите роль,
сохраните журнал, смените учётную запись, оцените необходимость уведомления
затронутых пользователей.

### `MODERATION_FAIL_CLOSED` как аварийный режим

Если классификатор ведёт себя непредсказуемо, переключите на локальный слой и
оставьте `MODERATION_FAIL_CLOSED=true` — контент уйдёт на ручную проверку, а
не будет опубликован без проверки.
